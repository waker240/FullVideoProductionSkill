# 审计循环(Audit Loops) — 该技能的反馈机制

自我改进层级。这份文件是**底材,调暗的**:在正常调用中不会被读取,只有在运行审计时才会被加载。它定义了 `video-content-strategy` 如何获得全新视角的批评——针对其*产出*,也针对*自身*——以及这些批评如何在不损害该技能的前提下,变成经过验证的修改。

> **为什么需要这个(主干 + EIF)。** 一个没有反馈循环的系统是开环的——它"用环境来获取预期信息,而不是修订自己的计划"(这正是最初导致懒惰默认模式的那种失败)。而制作者无法看见自己的盲区:构建出某个东西的那个上下文,恰恰是最没有能力批评它的上下文。解决办法是*处于干净上下文中的全新视角节点*——从未见过制作者推理过程的子智能体,各自携带不同的视角,它们之间的分歧就是信号。这正是 Algorithmic Complementarity(算法互补性,不同节点处理各自最擅长的计算类别)在质量控制上的应用。

> **让这个技能实现自我改进的递归结构。** 大多数技能都是静态参考资料。这一份技能能闭合这个循环:它可以审计自己的产出,把这些发现输入到对*自身*的审计中,并把经过验证的改进写回——同时有一道关卡,防止自我修改变成自身新的 slop 来源。这个技能因此成为一种演化式计算,而不是一件冻结的artifact。

## 两个循环(它们组合成一个系统)

```
        ┌─────────────────────────────────────────────────────────┐
        │                                                         │
        ▼                                                         │
  [ 已构建的场景/视频 ]                                            │
        │                                                         │
        │  LOOP A · 输出审计                                       │
        │  全新视角的子智能体批评交付物                              │
        ▼                                                         │
  [ 输出发现 ] ──┐                                                 │
        │        │ 跨视频反复出现的模式                             │
        │        │ (一个反复出现的发现不是                          │
        │        │  一次输出层面的 bug——它是一个技能层面的缺口)       │
        ▼        ▼                                                 │
  修复视频   [ 技能缺口信号 ]                                       │
                  │                                                 │
                  │  LOOP B · 技能审计                              │
                  │  全新视角的子智能体批评该技能本身                  │
                  ▼                                                 │
            [ 提议的修改 → audit-log.md ]                          │
                  │                                                 │
                  │  有门槛的写回                                    │
                  ▼                                                 │
            [ 经验证的修改被应用到技能上 ] ──────────────────────────┘
                  │
                  ▼
          下一个视频由一个更好的技能构建出来
```

**Loop A — 输出审计。** 全新视角的子智能体审阅一个*已构建*的场景或视频,报告哪里薄弱。它们的职责是交付物本身。该循环的产出:针对*这个*视频的具体修复,加上一份*哪些类型*的弱点反复出现的统计。

**Loop B — 技能审计。** 全新视角的子智能体审阅*技能本身*(SKILL.md / reference.md / field-notes.md),并提出修改建议。触发方式为:按节奏、按需,或者——最重要的——当 Loop A 在多个视频中反复发现**同一个**弱点时。一个反复出现的输出缺陷很少是一次性的失误;它是该技能*教会了*这个错误(或未能阻止它)的证据。这就是一个技能层面的缺口,会被路由到 Loop B。

**这种组合本身就是关键所在。** 单独的 Loop A 会永远地一个一个修视频(开环——该技能永远学不会)。单独的 Loop B 有可能在纯理论层面修改技能,却与真实产出毫无接触(Hologram(全息幻象)风险——听起来合理却不能改善视频的修改)。将两者接通:真实的产出失败成为技能修改的证据基础,而技能修改则要靠*下一次*输出审计是否不再标记该失败来验证。这种闭环,正是一个会漂移的技能和一个会复利积累的技能之间的区别。

## 不变量(对两个循环都成立)

- **始终保持干净上下文。** 每一个审计子智能体都从零开始——它绝不能继承制作者的推理过程、聊天历史,或其他审计员的发现。制作者的上下文就是被污染的上下文;审计的价值正在于它不共享这个上下文。(生成子智能体时,只给它:待审计的artifact + 它单一的视角授权 + 相关的技能摘录。绝不粘贴"这是我当初想达到的效果"。)
- **各视角并行且独立运行。** 一次审计中的所有视角要同时生成,彼此隔离。独立视角之间的收敛是最强的信号;如果让它们先看到彼此的笔记,它们会向一种观点collapse(审计本身就会向均值回归——见反模式部分)。
- **分歧是数据,不是噪声。** 当 Cinematographer(摄影指导)喜欢某个镜头,而 Naive Viewer(天真观众)却觉得困惑时,这种张力本身*就是*发现。不要把它平均掉;要把它呈现出来。
- **发现必须具体,否则就作废。** "第 2 幕感觉弱"是没用的。"第 037 镜的论点落地处没有暂停帧;档案牌卡和城市以相同速率运动,所以读起来像一个扁平的平面"才是可执行的。像该技能拒绝填充镜头一样,拒绝模糊的发现。
- **每一条发现都要点名它牵涉的主干条目或教条。** 一条无法追溯到某条主干规律(#1-6)或某个命名教条的发现,很可能只是品味,而非信号——将其记录为低置信度。

## 视角阵容(混合式:固定核心 + 一个轮换通配符)

每次审计运行都会生成**固定核心**(始终运行)加上从池子中抽取的**一个通配符**(每次运行轮换)。核心阵容提供一致性和对承重维度的覆盖;通配符则防止审计本身向均值回归——一个固定阵容如果永远运行下去,最终会出现制作者能够学会预先满足的可预测盲区。

### 固定核心(始终运行)

每个视角都是一个完整的人格,只有一种执念。子智能体要*成为*这个视角——不是"考虑"这个视角,而是将其代入到对其他一切都不公平的程度。(不公平正是重点:一个平衡的审计员是一个弱的审计员。)

| 视角 | 执念 | 它反复追问的那一个问题 | 牵涉 |
|---|---|---|---|
| **天真观众(The Naive Viewer)** | "我并不预先知道这些。你把我弄丢了吗?" | 在每一刻都在问:*我知道这是在讲什么、在论证什么、我们现在在哪里吗?*标记困惑、未解释的术语、丢失线索的瞬间。 | Receiver-Runway(接收者跑道,重新进入成本)、外化、分段 |
| **怀疑者/反平庸(The Skeptic / Anti-Slop)** | "这很泛。证明它不是。" | *这是不是均值——最安全、训练数据里最常见的动作?换成任何一个频道都能做出这个画面吗?*猎取装饰性内容、共识美学、没有经过发散就赢下来的 0 号想法镜头。 | Effort Protocol(努力协议)、Apex vs Hologram(顶点对全息幻象)、"我们不做什么" |
| **认知科学家(The Cognitive Scientist)** | "观众只有一个带宽固定的大脑。" | *这里在哪里让工作记忆过载、重复了某条信道(冗余),或未能实现双通道互补?*依据 Mayer/Sweller 进行审计。 | 主干 #2(带宽)、#3(外化)、互补性 |
| **摄影指导(The Cinematographer)** | "这是*被创作*出来的,还是*被拼装*出来的?" | *标志性动作在哪里?有暂停帧吗?镜头有自己的视点,还是只是壁纸?*审计惊艳感、120% 元素、Cinema-Layer 纪律。 | 惊艳诊断(Awe Diagnostic)、差异化原则(Differentiation Principle)、主干 #6 |
| **剪辑师/压缩主义者(The Editor / Compressionist)** | "剪掉一切配不上自己时长的东西。" | *什么可以在零损失的情况下被删除?节奏在哪里拖沓?EC/KC 比是多少——信号 vs. 填充?*审计密度节奏、时长纪律、复杂度-脆弱性极限。 | 主干 #1(连贯性)、密度节奏、目录纪律(Catalog Discipline) |

这五个视角与主干干净地一一对应:每条承重规律都至少有一个视角负责捕捉其违反情况。这就是覆盖保证。

### 通配符池(每次轮换一个——按 `date +%j` 对池大小取模选取,或在某次运行有明确侧重时刻意指定)

通配符是*对抗性的新鲜感*。它可以是奇怪的。池子如下:

1. **领域专家(The Domain Expert)** ——代入该视频实际主题的专家人格(经济学家、历史学家、该主题的认知科学家)。"这个视觉隐喻对机制本身是否*真实*,还是一个好看的谎言?"能捕捉误导性的隐喻。
2. **0.5× 注意力的移动端观众(The Mobile Viewer at 0.5× attention)** ——在手机上观看,半分心,有时静音。"这能扛住一块 4 英寸屏幕和分散的注意力吗?"对小字、字幕尺寸、任何需要靠声音才能理解的内容毫不留情。
3. **重复观看者(The Rewatcher)** ——已经看过这个视频三遍,也看过之前每一集。"我第一次错过了什么?重复观看有奖励吗?这是否和系列已建立的词汇表相矛盾或相呼应?"审计深度分层和系列一致性。
4. **EIF 审计员(The EIF Auditor)** ——在artifact上运行该框架自己的协议:硬件优先、EC/KC、象限定位、信道容量、跑道。"能量流向哪里;连贯性是什么;这处于哪个象限?"(这正是用来推导出主干的那个视角——让它保留在轮换中,以确保该技能与 EIF 保持一致。)
5. **恶意评论者(The Hostile Commenter)** ——评论区里最聪明、最刻薄的那个人。"槽点在哪?一个刻薄的观众会截哪张图来嘲讽?"捕捉无意的滑稽感、矫情、用力过猛、脱离语境后会显得不对劲的画面。
6. **竞品导演(The Competitor's Director)** ——这个领域里最好的那个频道的导演(Kurzgesagt / 3Blue1Brown / Wendover,视视频而定)。"换我来做这里,我会怎么做,而你没有那样做?"对标该类型的天花板。
7. **五年之后的观众(The Five-Years-Later Viewer)** ——在这个领域已经发生变化之后再来观看。"这里面有什么已经过时、追逐潮流,或与 Lindy 效应不兼容?什么会依然成立?"审计永恒性(约束一的 Lindy 主张)。
8. **无障碍审计员(The Accessibility Auditor)** ——色盲,或依赖字幕。"这套语义色彩系统能扛住红绿色盲(deuteranopia)吗?去掉颜色通道,意义会崩塌吗?"捕捉对色相的过度依赖来承载论证编码。

**通配符纪律:** 每次运行恰好一个。两个通配符会稀释核心阵容的信号,把审计变成一个委员会。通配符的发现与核心视角权重相同——新鲜感不是打折的理由。

## 运行 Loop A — 输出审计

**触发条件:** 一个锚点场景已构建完成;一幕已组装完成;一个完整视频渲染完成;或按需("审计这个场景")。

**流程:**

1. **为全新视角准备artifact。** 导出审计员实际要评判的东西:渲染后的 MP4(或该镜头关键帧的一组静帧)+ 该片段对应的旁白文本。审计员评判的是*输出*,而不是代码。(一个视角去读源代码,就是在审计错误的层面。)
2. **并行生成固定核心 + 一个通配符**,各自处于干净上下文,各自使用下方的提示模板。不要让它们互相看到对方。
3. **收集发现**,去重,并为每条发现打标签:哪个/哪些视角提出的、牵涉哪条主干规律/教条、严重程度(⚠️ 毁掉该镜头 / ⚡ 削弱该镜头 / 💡 打磨性建议)。
4. **修复视频**,针对 ⚠️ 和 ⚡ 级别的发现。
5. **为 Loop B 计数。** 把每条发现的*类别*追加到 `audit-log.md` 的"输出审计统计"部分。当某个类别越过复发阈值(见"写回")时,它就晋升为一个 Loop-B 技能缺口候选项。

### Loop A 子智能体提示模板

```
You are THE {LENS NAME}. {one-line persona}. Your single obsession: {obsession}.

You are reviewing a scene from an educational essay-video. You did NOT make it and
you do NOT know what the maker intended — judge only what is on screen and in the
narration. Be unfair: your job is to catch what your specific lens catches, not to
be balanced.

ARTIFACT: {path to MP4 / stills}
NARRATION (this span): {text}

Ask your lens's one question relentlessly. Then report ONLY specific, located findings:

  - [SEVERITY ⚠️/⚡/💡] [timestamp or shot id] — {what is wrong, concretely} —
    {which Spine line #1-6 or named doctrine it violates} — {the smallest fix}

If a finding isn't specific enough to act on, discard it. If the scene is genuinely
strong on your axis, say so in one line and stop — do not invent problems to seem useful.
Return 0-6 findings. Quality over quantity.
```

## 运行 Loop B — 技能审计(自我编辑)

**触发条件(任一即可):**
- **按节奏** ——每上线 N 个视频(默认:每 3 个),或用户设定的日历节奏。
- **按需** ——"审计这个技能"、"给技能来一次全新视角的审阅"。
- **来自 Loop A 的复发升级** ——某个缺陷类别越过了复发阈值(最强的触发条件;它意味着真实的产出正在以该技能允许的方式失败)。
- **事后复盘** ——某个已上线视频表现不佳,或某个具体镜头失败;审计该技能本应捕捉到什么。

**流程:**

1. **界定审计的问题。** 可以是开放式的("这个技能哪里最薄弱/最臃肿/内部最矛盾?"),也可以是有针对性的(携带 Loop-A 的复发信号:"视频反复在幕中段失守重新进入成本——技能里有什么未能阻止这一点?")。
2. **并行生成固定核心 + 一个通配符**,处于干净上下文,各自获得相关技能文件加下方的提示模板。EIF Auditor(EIF 审计员)通配符在此场景下是一个不错的默认选择。
3. **每个视角提出修改建议**——而不只是抱怨。一条没有配套修改建议的抱怨会被记录,但无法晋升。
4. **汇总收敛:** 将提议收集进 `audit-log.md`,以带置信度的假设形式呈现(见"写回")。注意各视角*一致*的地方(共识 → 更高置信度)和*冲突*的地方(冲突 → 保持低置信度,需要人工判断)。
5. **应用关卡。** 只有通过关卡的内容才会被写入技能;其余的一律留在暂存状态。

### Loop B 子智能体提示模板

```
You are THE {LENS NAME}. {one-line persona}. Your single obsession: {obsession}.

You are auditing a SKILL document that teaches an AI how to design educational videos.
You did NOT write it. Read it with fresh, unfair eyes through your lens ONLY.

SKILL EXCERPT(S): {paste SKILL.md and/or the relevant section(s)}
{if escalation:} TRIGGERING SIGNAL: real videos keep failing this way: {recurrence signal}

Through your lens, find where this skill is:
  - WRONG (teaches something that doesn't hold up on your axis)
  - MISSING (a gap your lens would never let pass)
  - BLOATED / INCOHERENT (EC overload — too much to apply, near the complexity-fragility limit)
  - CONTRADICTORY (two parts that fight)

For each, propose a SPECIFIC edit:

  - [WRONG/MISSING/BLOATED/CONTRADICTORY] [file §section] — {the problem} —
    PROPOSED EDIT: {concrete change — add this line / cut this section / reword to X} —
    {why this improves coherence-transfer-per-viewer-energy, the skill's core objective}

Bias toward COMPRESSION, not addition — this skill is already near its complexity-fragility
limit; "add another pattern" is usually the wrong answer. An edit that removes or merges
without losing signal is worth more than one that adds. Return 0-6 proposals.
```

## 有门槛的写回(让自我编辑变得安全)

一个自我编辑技能的危险显而易见:**自我修改会变成它自身新的 slop 来源。** 一个审计员听起来合理的提议,一旦被自动应用,可能会比任何单个差视频更快地败坏一个承重技能。所以写回是*有门槛的*——完整借用了 EIF Framework Evolution Protocol(框架演化协议)的置信度模型(以假设形式提出;只有获得证据才能晋升)。

### 置信度等级(当一条提议进入 `audit-log.md` 时赋予)

| 等级 | 含义 | 默认动作 |
|---|---|---|
| **Low(低)** | 只有一个视角提出;无印证;或它只是品味,无法追溯到某条主干规律。 | 暂存于 `audit-log.md`。不应用。若再次出现则重新审视。 |
| **Medium(中)** | 2 个以上独立视角收敛于此,或 1 个视角 + 一次 Loop-A 复发信号支持。可追溯到某条主干规律/教条。 | 暂存 + **呈报给用户**,附带提议的修改。经批准后应用。 |
| **High(高)** | 3 个以上视角收敛,或中等置信度 + 被一次该修改本可避免的真实输出失败所证实,且该修改是一次*压缩/澄清*(而非新模式)。 | **具备自动应用资格**(见关卡)。 |

### 关卡 — 什么可以自动应用,什么必须等待

自动应用被刻意设定得很窄。只有**全部**满足以下条件,修改才会自动应用:

1. **高置信度**(依据上表)。
2. **是减法性或澄清性的,而非新增性的。** 删减、合并、改写措辞、修正矛盾、纠正错误 → 有资格。*新模式 / 新章节 / 新词汇 → 永不自动应用*(新增会提高 EC 和维护成本;这类修改始终等待人工判断,依据目录纪律)。
3. **触及的是 SKILL.md/reference.md 的正文,而非锁定的承重集合。** 主干的六条规律、Style Register Library(风格register库)的锁定、导演单契约,以及 field-notes 中频道锁定的锚点坐标,均**禁止自动编辑**——这些是承重的墙(参照 EIF"不要触碰 6 大核心支柱"的规则)。针对这些内容的提议,无论置信度如何,始终呈报给用户,永不自动应用。
4. **自我记录在案。** 任何自动应用的修改都要在 `audit-log.md` 中追加一行带日期的记录(改了什么、由哪些视角驱动、当时的置信度),以便人类能审计这个审计者本身并可以撤回。

未能同时满足全部四项条件的 → 一律留在 `audit-log.md` 中暂存,等待用户。默认姿态是**暂存,不应用**:拿不准的时候,提议就等着。

### 晋升流程

```
lens proposal ──▶ audit-log.md (Low)
                      │ another lens / another video corroborates
                      ▼
                 audit-log.md (Medium) ──▶ surfaced to user ──▶ applied on approval
                      │ third corroboration + output-failure evidence + is-subtractive
                      ▼
                 audit-log.md (High) ──▶ [GATE] ──▶ auto-applied + logged
                                              │ fails any gate condition
                                              ▼
                                         surfaced to user
```

### 每次写回都要镜像同步

任何被应用的修改(无论是自动的还是经批准的)都必须**同等地写入两份技能副本**(`~/.cursor/skills/video-content-strategy/` 与项目内 `.kiro/skills/video-content-strategy/`),二者依契约应保持字节级一致。应用之后,用 `diff` 验证。一次只落在一份副本里的修改是一种损坏,而不是一次改进。

### 审计者审计自己(递归防护)

依据 EIF 的递归规则:审计机制本身也是系统中的一个节点,必须被审计。两项自查:

- **审计是否在向均值回归?** 如果最近几次审计产出了几乎相同的发现,说明视角阵容已经陈旧——更激进地轮换通配符,或淘汰一个总是一无所获的核心视角。一个可预测的审计员就是一个已被满足的盲区。
- **写回是否过度触发?** 如果自动应用的修改经常被用户撤回,说明关卡太松——提高门槛(要求每条 High 都必须引用一次输出失败)。如果从来没有内容达到 High,说明关卡太紧——检查各视角是不是根本没有提出修改建议,还是只是在抱怨。

## 节奏 — 何时运行什么

| 触发条件 | 循环 | 范围 |
|---|---|---|
| 锚点场景构建完成 | A(输出) | 该场景。轻量级——核心视角审视静帧。 |
| 一幕组装完成 | A(输出) | 该幕。完整核心 + 通配符,审视渲染后的 MP4。 |
| 视频渲染完成 | A(输出) | 整个视频。完整审计;这是输出审计价值最高的时刻。 |
| 每上线 3 个视频(默认) | B(技能) | 对该技能的开放式审计。 |
| Loop-A 类别越过复发阈值 | B(技能) | 携带复发信号的针对性审计。**价值最高的触发条件。** |
| 已上线视频表现不佳 | B(技能) | 事后复盘:该技能本应捕捉到什么? |
| 用户说"审计这个技能 / 来点新视角" | B(技能) | 按需。 |

**复发阈值(默认):** 同一个输出缺陷类别在 **3 个不同视频**中被标记(或 2 个视频 + 2 个视角在其中一个上达成一致)。如果触发过于频繁(噪声)或从不触发(阈值设得太高),在 `audit-log.md` 中调整。

**不要过度审计。** 审计本身也是能量支出(子智能体调用、人工审阅时间)——它遵循与其他一切相同的连贯性预算。只审计锚点级输出和技能节奏,不要每个功能性镜头都审。一个对所有东西都运行的审计,会训练团队去忽视它(警报疲劳 = 审计自身向噪声的回归)。

## 反模式(审计作为一个系统的失效方式)

- **被污染的上下文。** 生成审计员时把制作者的推理过程也带入了范围。它们会去附和,而不是挑战。整个价值就在于干净房间般的上下文——要保护它。
- **串行、偷看式的视角。** 一个接一个地运行视角,每个都能看到上一个的笔记。它们会收敛到一种观点;你会失去独立收敛这一信号。始终并行 + 隔离。
- **平衡的审计员。** 一个试图做到公平的视角,发现不了任何尖锐的东西。每个视角都必须*不公平*——对一个维度着魔到排斥其他一切。平衡应该发生在收敛阶段,而不是在单个视角内部。
- **有抱怨没提议(Loop B)。** "这一节很让人困惑"无法晋升。必须要求一条具体的修改提议,否则它就永远停留在 Low 这个层级。
- **增量性漂移。** 审计员喜欢提议新模式;新模式会把 EC 推向复杂度-脆弱性极限。要强烈偏向压缩;新增内容始终需要人工批准才能通过关卡。
- **自动应用蔓延。** 因为"审计员们通常是对的"而放松关卡。关卡的严苛正是安全所在。一次错失的好修改的代价(它会等待批准)很小;一次自动应用到承重技能上的坏修改的代价却很大。这是不对称的——保持关卡紧绷。
- **审计表演。** 运行这个循环只是为了*看起来*严谨,然后忽视其发现(或对每条提议都盖章通过)。两者都会让这个循环沦为噪声。发现必须改变视频或技能本身,否则这次审计就不该运行。
- **审计向均值回归。** 最深层的失败:审计阵容本身变得可预测,制作者学会了预先满足它,它就不再能捕捉到任何真实的东西。靠轮换通配符和上述自查来对抗——但要保持警觉:一个总是通过的审计,就是一个已经停止发挥作用的审计。

## 与其他部分的关联

- **主干(The Spine)**(`SKILL.md`) ——每个视角都要把自己的发现追溯到一条主干规律;主干就是审计的评判标准。
- **Effort Protocol(努力协议)/ 批评者环节(Critic Pass)**(`SKILL.md`) ——批评者环节是*制作者自己*的快速自我审计(一个头脑,切换帽子);输出审计是它的*全新视角*版本(多个干净上下文的头脑)。在宣布某个镜头完成之前先做批评者环节;在构建完锚点作品之后做输出审计。
- **`audit-log.md`** ——暂存台账,提议在晋升之前带着置信度等级停留于此。
- **`field-notes.md`** ——当一次 Loop-B 修改被应用时,*依据*和验证状态会被记录在那里(持久记录);`audit-log.md` 是*进行中*的台账(在途提议)。
- **EIF Framework Evolution Protocol(框架演化协议)** ——置信度/假设/晋升模型是直接借用的;如果该协议更新,请在此同步镜像该变化。
