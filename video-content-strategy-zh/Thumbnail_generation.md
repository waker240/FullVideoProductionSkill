# 封面图生成手册（通过 MCP 调用 gpt-image-2）

> **适用对象**：本工作区中被要求为一个视频「生成候选封面图」的下一个 agent。这是端到端、可直接复制粘贴使用的流程——模型、MCP 调用机制、提示词模板、4:3 技巧、迭代循环，以及文件命名约定。已于 2026-06 在视频 #7（education-ep3，苏格拉底）和视频 #8（predictive-processing）上验证。

本文档覆盖**生成式 PNG**封面图路径（gpt-image-2 渲染整张封面图，文字直接烘焙进图里）。至于另一条**基于 Remotion 合成**的路径（通过 `remotion still` 渲染 SVG + HTML 文字）以及帧提取兜底方案，参见 `video-content-strategy/thumbnail-extraction.md`。生成式 PNG 路径迭代更快，也是最近这几个视频所使用的方案。

---

## 0. 太长不看版——循环流程

1. **阅读视频素材**——旁白（`*-narration-plain.md`）、`theme.ts`、2-3 个场景文件。提炼出论点、最有力的钩子，以及已经确立的视觉母题。
2. **设计 3-4 个概念**，每个都是*不同的钩子*（而不是一个想法的多个变体）。把每个概念映射到一个不同的角度：冷开场钩子 / 论点 / 机制 / 结果反转。
3. **每个概念写一份 `req-*.json`**（五段式提示词，锁定调色板，4:3）。
4. **并行发送所有请求**，通过 `curl` 调用本地 MCP 服务器（4 次调用，每次一个 Shell 工具调用，放在同一条消息里）。每次耗时约 50-65 秒。
5. **读取输出的 PNG**，检查文字正确性、调色板、构图。
6. **保存**满意的结果到 `my-video/public/projects/<slug>/thumbnails/`，命名要有描述性；清理临时的 `req-*.json`。
7. **在用户最满意的方案上迭代**（视觉更含蓄/文字更大/角度不同）——同样的流程，1-2 个新变体。

## 1. 模型——只用 `openai/gpt-image-2`

本项目将图像生成锁定在 `openai/gpt-image-2`。在整套工具中，它是唯一能同时做到**多文字系统排版正确（汉字准确无误）**、**精确遵守十六进制调色板**、**严格遵循版式**，以及**低多边形风格化**的模型。封面图请勿使用 Imagen / Flux / Grok——它们会把汉字弄乱，调色板也会跑偏。

完整的模型选型理由见：`.cursor/skills/video-generation-mcp/SKILL.md` 和 `How_images_svgs.md`（项目根目录）。

## 2. MCP 调用机制

media-generation MCP 服务器在**本地**运行，地址为 `http://localhost:3105/mcp`（JSON-RPC 2.0）。有两种调用方式；**curl 是封面图场景下经过验证的路径**，因为提示词里含有汉字和大量引号——构建一个 JSON 文件并用 `--data-binary` 发送 POST 请求，可以完全避开 shell 转义的麻烦。

### 2.1 先确认服务器已启动

```bash
curl -s -X POST http://localhost:3105/mcp \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  --data-binary '{"jsonrpc":"2.0","id":1,"method":"tools/list","params":{}}' | head -c 400
```

如果它返回了一个包含 `generate_image` / `generate_video` 的工具列表，就说明一切正常。如果服务器没有在运行，`CallMcpTool` 工具（服务器 id 为 `project-0-Rem1-mediaGeneration`，工具为 `generate_image`）可以作为兜底方案——但这里更推荐用 curl。

### 2.2 请求 JSON 的结构

每个概念写一个文件（例如 `req-A.json`）：

```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "tools/call",
  "params": {
    "name": "generate_image",
    "arguments": {
      "model": "openai/gpt-image-2",
      "size": "1024x768",
      "output_dir": "/Users/jingyu/python/1WORKAGENTS/Remotion1/my-video/out/thumb-<slug>",
      "prompt": "<完整的五段式提示词——见第 4 节>"
    }
  }
}
```

- `output_dir` **必须是绝对路径**。在 `my-video/out/` 下为每一批用一个临时草稿目录（例如 `out/thumb-pp/`、`out/thumb-ep3/`）。服务器会把 `<uuid>.png` 写到那里并返回路径。
- 汉字可以直接内联，也可以用 `\uXXXX` 转义写入——在 JSON 文件里两种方式都可行。直接内联更清晰易读。

### 2.3 发起调用

```bash
curl -s -X POST http://localhost:3105/mcp \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  --data-binary @req-A.json | tail -c 500
```

响应（SSE 的 `event: message`）以如下内容结尾：

```json
{"image_paths":["/Users/.../my-video/out/thumb-<slug>/<uuid>.png"]}
```

### 2.4 并行处理

在**一条助手消息中发送 4 次 curl 调用**（4 个独立的 Shell 工具调用）。MCP 服务器会并发处理它们——4 张图片总共约 60 秒就能生成，而不是串行的约 4 分钟。把每个 Shell 调用的 `block_until_ms` 设为约 180000（3 分钟）以留有余量；每次调用实际上会在约 50-65 秒内返回。

## 3. 尺寸与宽高比——4:3 技巧

本频道的视频是 **4:3**（1440×1080）。所以封面图也应该是 4:3。

- gpt-image-2 **文档记载的尺寸**是 `1024x1024`、`1024x1536`、`1536x1024`。
- **真正的约束条件（2026-06 验证）：服务器接受任何宽和高**都能被 16 整除**的尺寸**——不只是那三个文档记载的尺寸。服务器会用如下方式拒绝非整除的尺寸：`Invalid size '1920x1080'. Width and height must both be divisible by 16.`（`1080 / 16 = 67.5` → 失败。）
- **`1024x768`（真正的 4:3）可以用**（两边都能被 16 整除）——已验证输出确实是 1024×768。**为 4:3 封面图使用 `1024x768`**，这样就不需要裁剪。
- **`1536x864`（真正的 16:9）可以用**（1536÷16=96，864÷16=54，比例正好是 16:9）——用这个尺寸原生生成 16:9 封面图，无需裁剪。`1920x1080` **不能用**（1080 不能被 16 整除）；如果需要 1080p，可以把 `1536x864` 放大。
- 如果你不得不退而求其次使用不匹配的宽高比，就在提示词中加一条**安全区域**指令（把所有内容保持在中间约 75-88% 的宽度内，把边缘当作可丢弃的留白），然后手动裁剪。但更推荐通过一个能被 16 整除的尺寸直接生成所需的精确宽高比。

生成之后**务必核实实际输出尺寸**：

```bash
sips -g pixelWidth -g pixelHeight <uuid>.png 2>/dev/null | grep pixel
```

## 4. 提示词模板——五段结构

每张封面图的提示词都使用同一个结构。复制下面这个骨架，逐个概念填入 SUBJECT（主体）与 COMPOSITION（构图，即文字）；同一批内所有概念的 STYLE（风格）/ PALETTE（调色板）/ ANTI-SLOP（反低劣清单）应保持基本一致，让整套图看起来像是「同一家的」。

```
ASPECT RATIO — this is a true 4:3 landscape frame (width:height = 4:3). Compose
full-bleed for 4:3, edge to edge, no letterboxing, no disposable margins.

TEXT IS THE HERO — the Chinese headline must DOMINATE, covering at least 55-60%
of the frame. The illustration is restrained atmosphere, never competing.

STYLE — sophisticated minimalist editorial low-poly thumbnail. Faceted geometric
forms, 120-180 visible flat polygon facets, hard edges, matte drawn-not-rendered
surface, faint paper grain, cool diffuse museum light. NO smooth curves, NO 3D
glossy shading, NO Pixar softness, NO mobile-game cleanness, NO loud glow.

PALETTE — strictly limited. Background = #0A0E14 near-black. <neutral subject> =
#4A7C9B steel blue with #1a1f28 shadows. <tension/problem element> = #E8913A
amber. <insight/resolution element> = #3EC9A7 cyan-green. Headline = #E8E4DF
warm off-white, accent line = #3EC9A7. NO purple, NO neon bloom, NO rainbow,
NO gold gradient.

SUBJECT — <the low-poly illustration, kept to the LEFT ~30-35% of the frame at
low visual weight. Describe the metaphor concretely. Assign palette roles by
meaning: steel-blue = neutral/baseline, amber = the problem/void/tension,
cyan-green = the insight/guess/resolution.>

BACKGROUND — full-bleed #0A0E14, very faint angular grid at 3% opacity, one soft
low-opacity radial seating the text. Generous dark negative space.

COMPOSITION — <subject> hugs the left; GIANT text owns the rest. Bold heavy black
Chinese sans-serif slab. Line 1 reads exactly "<line 1>" and line 2 reads exactly
"<line 2>", both ENORMOUS in #E8E4DF off-white, each character bold and
commanding, stacked center-right. A clearly smaller third line below in #3EC9A7
reads exactly "<kicker>". <Optionally: tint one key word #E8913A or #3EC9A7 for
emphasis.> Dark drop-shadow for legibility only, no colored glow.

ANTI-SLOP — every Chinese character spelled correctly, no garbled glyphs, no extra
fake text, NO watermark, NO signature, NO logos, NO English text (except literal
"AI" if needed), NO border, NO chart axes, NO photographic realism, <+ subject-
specific exclusions, e.g. NO realistic anatomy, NO robot mascot, NO glossy chrome>.
```

### 4.1 锁定的调色板（务必记牢/精确复制）

| 角色 | 十六进制值 | 用途 |
|---|---|---|
| 背景 | `#0A0E14` | 近黑色底色 |
| 体系 / 中性 | `#4A7C9B` | 钢蓝色——基线主体、头颅/骷髅、当前状态 |
| 张力 / 问题 | `#E8913A` | 琥珀色——虚空、裂缝、张力、正在破裂的东西 |
| 洞见 / 解决 | `#3EC9A7` | 青绿色——猜测、填补、论点、修正 |
| 文字 | `#E8E4DF` | 暖白色标题 |
| 阴影面 | `#1a1f28` | 暖近黑色 |

这些是项目全局的语义色彩（来自 `the-filter/theme`）。**色彩是结构性的，而非装饰性的**——虚空是琥珀色，因为它就是*问题*本身；大脑的猜测是青色，因为它就是*洞见*本身。绝不要为了好看而重新配色。

## 5. 设计流程——如何选出 3-4 个概念

不要生成一个想法的 4 个变体。要生成 **4 个不同的钩子**，让这一整套图形成一次真正的 A/B 测试组合。从旁白中挖掘以下几类角度：

| 角度 | 是什么 | 示例（视频 #8） |
|---|---|---|
| **冷开场钩子** | 最具体、最感性冲击、最可验证的论断 | "你眼睛里有个黑洞，你却从没见过它"（盲点） |
| **论点** | 视频要植入的核心重构框架 | "你脑子里没有作者，只有一个旁白" |
| **机制** | 「它是如何运作的」的图像 | "你看到的世界，是大脑猜出来的"（骷髅在猜测） |
| **结果反转 / 镜像** | 重新解读一切的结尾式转折 | "你嘲笑 AI 只会猜下一个字，你的大脑也一样" |

对每个概念：
1. 挑出**最有力的 1-2 行标题**（标题文字本身就要占据画面的 55% 以上）。
2. 从**视频自身的母题**中挑一个视觉隐喻——先阅读场景文件，让封面图与实际动画产生呼应（例如 #8 中已经有了一个黑暗的骷髅、一个盲点式的虚空、一个分裂的大脑、一面 AI 镜子；#7 中有一条发散曲线和一座低多边形苏格拉底半身像）。复用这些元素，不要凭空发明无关的意象。
3. **按含义**分配调色板角色（见第 4.1 节）。
4. 把插画部分保持在**左侧约 30-35%**，文字主导右侧。

### 标题撰写技巧

- **最多 2 行主标题**，外加一行可选的更小的引导句。
- 主标题要**极其巨大**——必须在 320px 宽的缩略图尺度下、在手机上也能看清。
- 给**一个**关键词染上琥珀色或青色以形成视觉焦点（例如「黑洞」染琥珀色，「猜」染青色，「旁白」染青色）。不要染超过一个词。
- 在提示词中**逐字、按顺序**引用每一个字（`reads exactly "..."`）。模型会精确渲染你写的内容——提示词里的一个错字会变成一个完美渲染出来的错字。

### 5.1 风格register——不止一种自研低多边形风格

第 4 节的模板（`#0A0E14` 底色上的低多边形编辑风）是**默认的自研风格**——安全、符合品牌调性，当封面图应该与视频自身的动画相呼应时，这是正确的选择。但它只是一种register，不是唯一的一种。对于一个钩子本身就是一个*可识别的真实世界物件*（一则招聘广告、一段聊天记录、一份泄露的文件）的情况，一张模仿真实媒介质感的封面图，其点击率可能会超过编辑风格的图，因为它在观众意识到这是内容之前，就已经先读作了「真实的东西」——解码成本几乎为零。已于 2026-06 在视频 #12（education-ep5）上验证。

当一个概念的钩子本身就是某种物件时，就用那种物件对应的register来生成，而不是硬套低多边形风格。候选register如下（均已验证）：

| Register | 模仿的对象 | 最适合 | 关键提示词杠杆 |
|---|---|---|---|
| **真实招聘公告板** | 一张钉在公告板上的纸质招聘传单，或一块发光的 LED 点阵招聘会告示牌 | 荒谬矛盾类梗图（例如「招应届生 / 要十年经验」）；两行式的笑点本身就是整张图 | 陈旧纸张 `#F4EDE0` + 生锈图钉 + 轻微倾斜；或者黑色 LED 面板配点阵字符，第一行琥珀色 / 第二行热红色。只保留那两行矛盾的文字，其余全部去掉。 |
| **微信群聊截图** | 一个深色模式的微信聊天界面：一张被分享的招聘广告卡片 + 一句面无表情的神回复 | 高度自我相关的社交类钩子；最大化的原生传播力 | 聊天背景 `#191919`，灰色 `#3A3A3A` 气泡（对方）配左侧头像，绿色 `#07C160` 气泡（你）右对齐且**不带**右侧头像；气泡尾巴增加真实感。**放大约 2 倍，让两个气泡填满画面**——这样既能在 320px 尺度下保持文字清晰，又能让人一眼认出这是真实截图。 |
| **低多边形编辑风** | 默认自研风格——近黑底色上的多面体几何形态 | 应该与视频自身动画/母题相呼应的封面图 | 完整的第 4 节模板。这是「安全」的选择；对大多数集数来说仍是正确的默认方案。 |
| **纵深优先** | 一个密集、多层、具有强烈纵深透视和电影级景深的三维场景——重点在于*处理手法*，而不是特定主体。主体可以是**任何东西**（一个多面体物件、一件设备、一张示意图、层叠的平面、一片粒子/文字场、一群人、一个向消失点延伸的建筑空间）；重点是大量视差层、近景模糊 → 中景清晰 → 消失点处的尘埃，以及压倒性的纵深感与密度感。标题保持锐利清晰，始终位于最前景，压在模糊的场域之上 | 「压倒性」、极繁主义、以规模/密度/深度本身作为卖点的大议题集数；应该给人以三维、丰富的感觉，而非平面编辑风的封面图 | 反转了第 4 节「插画克制」的规则——密集的层叠场域*本身*就是奇观，但文字仍要保持清晰、位于最前。详见下方专门的说明。 |
| **涂黑机密文件** | 一份复印/泄露出来的文件，带有大片黑色涂黑条，加一个斜盖的「机密」/ "CLASSIFIED" 印章 | 「有人藏起了这个」式的挑衅型钩子（打压、隐藏的排序） | 泛黄的复印纸，主体上覆盖着密集不透明的黑色条块，琥珀色印章约 60% 不透明度，轻微的扫描倾斜（0.5-1°）。主标题就是「审查者漏掉的那一部分」。 |
| **大声量标题党脸**（B站/MrBeast register） | ONE giant exaggerated FACE 怼到镜头极近（cropped at edges），表情夸张，配一句不超过 6 个字的口号 | 追求最大唤醒度、覆盖面最广的集数；当你想要的是原始的、能让人停止下滑的冲击力，而不是精致感的时候 | 见下方专门的说明——这个register有硬性规则。 |

其他已经探索过、留待需要时使用的register：**苏式建构主义宣传海报**（血暗色调、炽热的红橙色、宣传画式的能量感）、**控诉式白光曝光**（近白色的过曝背景、锐利的剪影——在深色信息流中形成最大反差）、**街头涂鸦模板风**（水泥墙、滴漆、抗议式的紧迫感）、**热成像/X 光扫描**（半透明主体、内部机制若隐若现）。

非默认register的使用纪律：
- **仍然要核对汉字。** 模仿真实媒介的风格（LED 点阵、做旧/洇墨的纸张、放大的截图）是汉字乱码风险**最高**的类型——务必检查输出，任何字符不对就重新生成。
- **物件本身必须承载论点**，而不只是一层皮。聊天截图之所以有效，是因为那句*回复*重构了这个笑点；涂黑之所以有效，是因为被隐藏的东西*就是*论点本身。如果这个媒介只是纯粹的装饰外壳，就改用自研低多边形风格。
- **同一批 A/B 测试中，每个概念只用一种register**——把同一个钩子在 3-4 种register之间生成（从写实到风格化都试一遍），看哪种媒介效果最好，再在获胜的那个上继续迭代。
- **对这些register来说，调色板可以脱离自研体系**（微信绿、LED 红、复印纸黄都是符合该媒介本身特质的颜色）——但仍要把琥珀色/红色留给制造笑点的那个元素，让视线依然落在论点想要它落的地方。

#### 纵深优先register——各项杠杆（与主体无关）

这是一种*处理手法*，而不是特定主体。当封面图应该让人感觉三维、多层、密度压倒一切，而不是平面编辑风格时使用——当纵深/规模/密度本身就在推销这个大议题时使用。主体可以是这一集所需要的任何东西（一个多面体物件、一件设备、一张爆炸图、层叠的半透明平面、一片粒子/文字场、一群人、一个向消失点延伸的建筑内部空间）。已于 2026-06 在视频 #13（维特根斯坦——由暖到冷的层叠文字面）上验证。各项杠杆（每一条都是承重的）：

- **多层视差纵深，而不是单一平面。** 明确要求近景、中景，以及向消失点/边缘尘埃处延伸的远景。用「几十层」「数以万计的粒子」「向后延伸的层叠」——把密度明确说出来。单一的平面图层会毁掉这个register。
- **电影级景深是核心技巧。** 近景略微**模糊**，中景平面**锐利**对焦，远景消融进雾霭/黑暗中。这正是让画面读作「三维/在空间中拍摄」而非「矢量插画」的关键。始终要求它。
- **标题豁免于模糊——保持锐利、位于最前景。** 密集的场域存在于文字*背后*。要说明标题是锐利清晰、位于最前景、且是唯一的大号可读文字；场域中的一切都应是微小/抽象的纹理。这正是在不牺牲 320px 尺度下可读性的前提下，做出「压倒性」效果的方法。
- **纵深可以通过层与层之间的渐变来承载论点。** 一次贯穿纵深轴的转变正合题意：近景是暖色/人性化 → 远景是冷色/机械化（视频 #13），或已知→未知、当下→历史、单一→众多。观众的视线沿 z 轴移动，读出论点。
- **让锁定调色板与纵深共同发挥作用。** 底色仍是 `#0A0E14`，语义化的琥珀色/青色，手绘而非渲染质感的多面体表面，淡淡的颗粒感。不要平滑光泽的三维效果，不要皮克斯式的柔和，不要手游式的干净，不要霓虹光晕——纵深感来自分层 + 景深 + 透视，而不是光泽渲染或光晕。
- **按精确的 ÷16 比例生成**（16:9 用 1536×864，4:3 用 1024×768）。更窄的 4:3 画幅会把各层压得更紧密，读起来密度感更强——直接生成所需的比例，而不要裁剪，因为裁剪会吃掉正在向后延伸的边缘。
- **仍然要核对汉字**——繁忙的场域会诱使模型偷偷把假字形文字塞进可读区域；确认标题字符准确无误，且场域始终保持抽象/微小。

#### 大声量标题党脸register（B站/MrBeast 风）——硬性规则

这是与自研编辑风截然相反的一极：最大唤醒度、最少元素。当目标是追求原始的传播覆盖面和让人停止下滑的冲击力，而非精致感时使用。已于 2026-06 在视频 #12（瞪羚/震惊的毕业生/野狗/爆裂的毕业证组图）上验证。以下规则（每一条都是承重的——破坏任何一条，图就会读作一张软弱的编辑风封面图，而不是一张够「响」的封面图）：

- **一个主体，怼到镜头极近。** 把主体推得极其靠近镜头，以至于在画面边缘被轻微**裁切**（近大远小）。粗黑描边，极端反差，夸张到几乎装不下整个画面。
- **主体几乎总是一张脸。** 脸是唤醒度最高的视觉载体。表情要夸张——癫狂的笑容、鬼畜、瞪大的眼睛、张大的嘴巴、明亮的白色高光眼神，配以淡淡的速度线/动态模糊来增加能量感。动物的脸（这一集里的瞪羚/野狗）以及食物/物体的特写也同样有效；一个被毁坏的物体（一本爆裂的毕业证）就是尖叫的脸的物体版本。
- **项目硬性约束——不允许照片级真实的人类。** 本频道禁止使用照片级真实的人物（见 `How_images_svgs.md`）。所以人脸要渲染成**夸张的粗线条卡通**或低多边形风格，绝不能是照片级写实的。取自视频自身母题库的动物/物体，是最安全的「响亮」型主体。这是唯一一处「响亮」register要向项目硬性规则让步的地方——绝不生成照片级真实的人脸。
- **文字不超过 6 个字，黑体，禁止艺术字体。** 一旦文字变得巨大，就只剩下容纳**一个**主体的空间了。用极简的粗体无衬线字体，让任何人都能一眼读懂（例如「装不出来」「白读了」「换一个」「废纸一张」）。禁止艺术字，禁止装饰性字体处理。
- **大红 / 大黄 / 大白，硬反差，禁止渐变。** 平涂的炽热色块（红色 `#E60012`、黄色 `#FFD400`、白色 `#FFFFFF`），文字用一种纯色搭配一圈粗重的对比色描边（黄底红字配白色描边；红底黄字配黑色描边）。禁止小清新渐变，禁止霓虹光晕。
- **仍然要核对汉字**——大号黑体通常比较干净，但四字口号也可能出现笔画错误。检查后如有问题就重新生成。



以下几条直接来自与用户在视频 #7 和 #8 上反复迭代的经验。

- **文字的主导地位不容商量。** 当用户说「文字再大一点」，他们的意思是文字应该*主导*画面。把主标题推得更大，把插画部分缩小或挪个位置。
- **「含蓄/精致」不等于字面意义上的图表。** 当被要求让视觉效果更含蓄时，要用**抽象**的方式来表达这个想法（相互对抗的多面体力量、一片虚空、粒子的漂移），而不是一张带标签的图表或一条折线图。用户曾明确拒绝了字面意义上的发散*曲线*，转而选用抽象的对抗性力量。
- **不要落入光晕陷阱。** 深色投影**仅**用于提高可读性。这些语义色彩在 `#0A0E14` 上本身就已经足够醒目；再加上彩色光晕就会显得像是一个手游广告。提示词中要始终包含「no colored glow」和「NO neon bloom」。
- **低多边形是默认选项，不是铁律。** 对于自研编辑风register，始终包含「120-180 visible flat polygon facets」「drawn-not-rendered」以及完整的一组否定性条款（禁止三维光泽、禁止皮克斯风、禁止手游式干净）——没有这些条款，模型就会漂移向平滑渲染。**但**当某个概念的钩子本身就是一个真实世界的物件（招聘广告、聊天记录、泄露文件）时，就改用那个物件对应的register（见第 5.1 节）——不要把低多边形硬套在一张全部魅力都在于「读起来很真实」的封面图上。
- **每次都要加上反低劣清单。** 「每一个汉字都拼写正确，没有乱码字形，没有多余的假文字」这句话能可衡量地减少字形错误。再加上针对该主体的专属排除项（禁止写实的解剖结构、禁止机器人吉祥物等）。
- **核对渲染结果。** 始终**读取**输出的 PNG，检查：(a) 汉字是否正确、没有乱码，(b) 调色板是否守住（或该register预期的调色板），(c) 文字是否占主导，(d) 尺寸是否匹配目标宽高比。任何一项不合格就重新生成。模仿真实媒介的register（LED 点阵、做旧纸张、放大截图）是字形出错风险最高的类型——在这些情况下要最严格地审查汉字。

## 7. 文件与命名约定

- **草稿目录**（临时，可随时清空）：`my-video/out/thumb-<slug>/` —— 存放 `req-*.json` 以及原始的 `<uuid>.png` 输出。
- **交付目录**（提交入库）：`my-video/public/projects/<project-folder>/thumbnails/` —— 把满意的结果复制到这里，使用**有描述性的名字**：`candidate-<n>-<concept>.png`（例如 `candidate-1-blind-spot.png`、`candidate-4-ai-mirror.png`）。
- 批次结束后**清理**临时的 `req-*.json`（`rm -f .../req-*.json`）。原始的 uuid 命名 PNG 可以留在草稿目录里，也可以删除；只有 `thumbnails/` 里那些有名字的副本才重要。

## 8. 实操示例（视频 #8 —— predictive-processing，2026-06）

1. 阅读 `predictive-narration-plain.md` → 论点：大脑是一台猜测机器；感知（盲点、椅子）、决策（Libet）、以及自我（分裂脑「解释者」/旁白）都是事后建构的；AI（「只是在猜下一个字」）就是这面镜子。阅读 `theme.ts`（确认了锁定的调色板 + 4:3）以及 `DarkSkull.tsx` / `BlindSpot.tsx`（母题：黑暗的骷髅、从一道细细的琥珀色信号中生出的青色幽灵世界；被琥珀色环绕的虚空，被青色幽灵填补）。
2. 四个概念 → 四个钩子：A 盲点，B 无作者/旁白，C 骷髅在猜测，D AI 镜子。
3. 写出 `out/thumb-pp/req-A..D.json`，`size: "1024x768"`，锁定调色板，第 4 节的模板配上每个概念自己的隐喻和逐字标题。
4. 并行发起 4 个 curl 请求 → 约 60 秒内得到 4 张 PNG。
5. 逐一`读取`，验证汉字正确、调色板正确、尺寸为 1024×768。
6. 复制到 `public/projects/8-predictive_processing/thumbnails/candidate-{1..4}-*.png`，删除 `req-*.json`。

上述模板可以完整复现所用的确切提示词；每个概念之间唯一的差异只是 SUBJECT 隐喻和那两行标题文字。
